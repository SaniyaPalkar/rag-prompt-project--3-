# NoteFusion backend

Node.js + Express. RAG (local embeddings + vector search) plus a knowledge graph, with answers generated by OpenRouter.

## Run

```bash
cd notefusion-backend
npm install            # installs the new auth packages too
cp .env.example .env     # then put your OPENROUTER_API_KEY in .env
npm run dev
```

First upload downloads the embedding model (~25 MB, needs internet once).
Test: open http://localhost:5000/api/health

## API

| Method | Route | What it does |
|---|---|---|
| POST | `/api/auth/register` | `{ name, email, password }` creates an account and logs in |
| POST | `/api/auth/login` | `{ email, password }` |
| POST | `/api/auth/logout` | clears the login cookie |
| GET | `/api/auth/me` | current user, or 401 |
| POST | `/api/upload` | multipart, field `files` (PDF, image, audio, .txt/.md), optional `lectureDate` |
| GET | `/api/library` | list uploaded documents |
| GET | `/api/models` | models available in the dropdown (installed Ollama models) |
| GET | `/api/files/:docId` | open one of your own uploaded files |
| DELETE | `/api/library/:id` | remove a document from files, vectors and graph |
| POST | `/api/chat` | `{ chatId?, message, model? }` returns `{ chatId, title, answer, sources, concepts }` |
| GET | `/api/chats` | sidebar history (pinned flag included) |
| GET | `/api/chats/:id` | full chat with messages and sources |
| PATCH | `/api/chats/:id` | `{ title?, pinned? }` |
| DELETE | `/api/chats/:id` | delete a chat |
| GET | `/api/graph` | `{ nodes, links }` for the Knowledge Graph page |
| GET | `/api/health` | status and counts |

All routes below `/api/auth` require a logged-in user, and each user only sees their own files, vectors, graph and chats.

## AI engine (Ollama or OpenRouter)

Set `LLM_PROVIDER` in `.env`. **Ollama** runs the models on your own computer: free, no rate limits, and your notes never leave your machine. **OpenRouter** uses cloud models and needs an API key.

For Ollama:
1. Install models (names are what `ollama list` shows):
   ```
   ollama pull llama3.2            # answers and concept extraction
   ollama pull llama3.2-vision     # reading handwritten notes and diagrams from photos
   ```
   Any installed chat model works: set `CHAT_MODEL` and `EXTRACT_MODEL` in `.env`. `VISION_MODEL` must be a model that can read images.
2. Make sure Ollama is running (the app or `ollama serve`).
3. Start the backend. It prints which models are missing and the exact `ollama pull` command.

The model dropdown in the chat box lists whatever is installed. Embeddings (for search) are always computed locally by the backend, so switching providers never invalidates your stored vectors.

Tips: 7 to 8 billion parameter models answer and extract concepts noticeably better than 3 billion ones if your RAM allows (about 8 GB free for a 7B model). Photo reading on CPU can take a minute or more per image. `OLLAMA_NUM_CTX` (default 8192) is the context window: Ollama's own default is small and would silently cut off your retrieved notes.

## Database (MongoDB)

Everything is stored in MongoDB: users, uploaded-file records, passage vectors, knowledge graphs and chats. Uploaded files themselves stay on disk in `uploads/<userId>/`.

1. Get MongoDB, either way:
   - **Local:** install MongoDB Community Server and leave it running. The default `MONGODB_URI` in `.env.example` already points to it.
   - **Atlas (free, no install):** create a free cluster at mongodb.com/atlas, add a database user, allow your IP, copy the connection string into `MONGODB_URI` in `.env`.
2. `npm install`, then `npm run dev`. The console should say `MongoDB connected`.
3. **Already have data from the JSON version?** Run `npm run migrate` once. It copies your account (same password), library, passages, graph and chats into MongoDB and leaves the old `data/` folder as a backup.

| Collection | Holds | Indexed by |
|---|---|---|
| `users` | name, unique email, bcrypt hash, role | email |
| `docs` | one record per uploaded file | userId + docId |
| `chunks` | passage text + embedding | userId + chunkId |
| `chats` | title, pinned, messages with sources | userId + updatedAt |
| `graphs` | one knowledge graph per user | userId |

Vector search scores the current user's passages in Node, which is fine for a personal library. For very large libraries, MongoDB Atlas Vector Search is the upgrade path.

## Authentication and authorization

- **Authentication:** email and password. Passwords are hashed with bcrypt, 8 to 72 characters, with rate-limited login. The session is a signed token in an `httpOnly` cookie (7 days). On every request the user is looked up in MongoDB, so a deleted account stops working at once.
- **Authorization:** the user id comes only from the verified token (`req.user.id`), never from the request body or URL. Every database query is filtered by that id, so one user cannot read, change or delete another user's chats, files, passages or graph.
- **Files** are not served by path. `GET /api/files/:docId` looks the file up in MongoDB for the logged-in user. Someone else's file id returns the same 404 as a missing one.
- **Roles:** each user has `role` (`user` or `admin`). `requireRole("admin")` in `src/middleware/auth.js` protects admin-only routes when you add them.
- Inputs are cast to strings before queries, which blocks NoSQL operator injection like `{"$gt": ""}`.
- Not included: email verification, password reset, "log in with Google".
- Set `JWT_SECRET` in `.env` for production (see `.env.example`).

## Connect the frontend

1. In `notefusion-ui/vite.config.js` add a proxy so `/api` and `/uploads` reach the backend:

```js
export default defineConfig({
  plugins: [react(), tailwindcss()],
  server: {
    proxy: {
      "/api": "http://localhost:5000",
    },
  },
});
```

2. Create `src/api.js`:

```js
export async function sendChat({ chatId, message, model }) {
  const res = await fetch("/api/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ chatId, message, model }),
  });
  const data = await res.json();
  if (!res.ok) throw new Error(data.error || "Request failed");
  return data;
}

export async function uploadFiles(files, lectureDate) {
  const form = new FormData();
  [...files].forEach((f) => form.append("files", f));
  if (lectureDate) form.append("lectureDate", lectureDate);
  const res = await fetch("/api/upload", { method: "POST", body: form });
  return res.json();
}
```

3. In `App.jsx`, add `const [chatId, setChatId] = useState(null);` and replace `handleSend`:

```jsx
const handleSend = async () => {
  const text = input.trim();
  if (!text) return;
  setInput("");
  setMessages((prev) => [...prev, { role: "user", content: text }]);
  try {
    const data = await sendChat({ chatId, message: text, model });
    setChatId(data.chatId);
    setMessages((prev) => [...prev, { role: "assistant", content: data.answer, sources: data.sources }]);
  } catch (err) {
    setMessages((prev) => [...prev, { role: "assistant", content: "Error: " + err.message }]);
  }
};
```
Also set `setChatId(null)` inside `handleNewChat`.

## Notes
- Uploaded files are stored in `uploads/<userId>/`. To reset everything, drop the `notefusion` database and delete `uploads/`.
- Free OpenRouter models are rate limited. Ingestion retries automatically, and a failed concept extraction never loses the upload (RAG still works, that chunk just has no graph links).
- Handwriting and diagram reading is done by the vision model (`VISION_MODEL`), not Tesseract, because Tesseract is poor on handwriting.
